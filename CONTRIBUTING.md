- **Respectful Communication**: Treat all contributors, maintainers, and community members with respect.

## How to Contribute

### 1. Reporting Issues

Found an error, outdated information, or a tool that should be added?

- **Check existing issues first** to avoid duplicates.
- **Create a new issue** with:
  - A clear, descriptive title
  - Detailed description of the problem or suggestion
  - Links to relevant documentation or sources
  - Screenshots (if applicable)

### 2. Suggesting New Tools or Platforms

Have a CRQ platform or open-source project to recommend?

- **Provide comprehensive details**:
  - Official product/project name and website link
  - Company/organization information (size, valuation, revenue, funding)
  - Clear description of core CRQ functionality
  - Accurate pricing information (if applicable)
  - Free tier or trial policy details
  - GitHub repository link (for open-source projects)
  - Star count (for open-source; sourced from GitHub)

### 3. Improving Existing Content

Help us keep the repository accurate and well-maintained:

- **Correct outdated pricing or company information**
- **Expand descriptions** with more technical details
- **Add missing information** (e.g., trial periods, free tiers)
- **Improve formatting** and clarity

## Contribution Guidelines

### For SaaS & Commercial Platforms

1. **Sorting Order**: Insert entries in **descending order by company valuation/market cap/funding size**.
2. **Required Fields**:
   - Platform/Tool name (with official link)
   - Company size/stage (e.g., Public, Private Series C, Acquisition status)
   - Market valuation or last funding round
   - Annual recurring revenue (ARR) if public
   - Description of CRQ capabilities and focus areas
   - Pricing tier information (entry price, scaling, enterprise tiers)
   - Free tier or trial policy with specific limits/duration

3. **Accuracy Standards**:
   - Use official company websites and press releases for valuation and revenue data.
   - Pricing should reflect the most current publicly available information.
   - Free trial durations and limits must be verified from official sources.

### For Open-Source Projects

1. **Sorting Order**: Insert entries in **descending order by GitHub star count**.
2. **Required Fields**:
   - Project name (with GitHub repository link)
   - Emoji identifier (thematic to the project)
   - Brief description of functionality and CRQ relevance
   - Key features or use cases
   - Primary language(s)

3. **Accuracy Standards**:
   - Verify the GitHub repository is actively maintained or clearly documented as archived.
   - Star counts should reflect the project's current GitHub metrics.
   - Descriptions should be factual and neutral (avoid marketing language).

### General Best Practices

- **Be Objective**: Use neutral, descriptive language. Avoid promotional or biased terms.
- **Verify Information**: Double-check all claims with official sources.
- **Maintain Consistency**: Follow existing formatting, structure, and emoji conventions.
- **Link to Sources**: Include official documentation and product pages.
- **Update Regularly**: If you maintain an entry, commit to keeping it current.

## Submission Process

### Step 1: Fork the Repository

```bash
# Click the "Fork" button on GitHub
```

### Step 2: Clone Your Fork

```bash
git clone https://github.com/YOUR-USERNAME/crq-repository.git
cd crq-repository
```

### Step 3: Create a Feature Branch

```bash
git checkout -b add-new-crq-tool
# or
git checkout -b update-pricing-info
# or
git checkout -b fix-documentation
```

### Step 4: Make Your Changes

- Edit `README.md` or other relevant files.
- Follow the guidelines above for format and content.
- Ensure spelling and grammar are correct.

### Step 5: Commit Your Changes

```bash
git add README.md
git commit -m "Add [Tool Name] to SaaS platforms section"
# or
git commit -m "Update pricing for [Tool Name]"
# or
git commit -m "Fix typo in CONTRIBUTING.md"
```

### Step 6: Push to Your Fork

```bash
git push origin add-new-crq-tool
```

### Step 7: Create a Pull Request

- Go to the original repository on GitHub.
- Click **"Compare & pull request"**.
- Write a clear PR title and description:
  - **Title**: "Add [Tool Name] to SaaS Platforms" or "Update [Tool Name] Information"
  - **Description**: Explain what you added/changed and why. Include links to sources.
- Submit the pull request.

## Pull Request Checklist

Before submitting a pull request, ensure:

- [ ] **Information is accurate and current** (verified from official sources)
- [ ] **Entries are in the correct sorted order** (by valuation for SaaS, by stars for open-source)
- [ ] **All required fields are present** (Name, link, description, pricing/funding, free tier)
- [ ] **Formatting is consistent** with existing entries (markdown syntax, emoji use, table structure)
- [ ] **No duplicate entries** (check if the tool is already listed)
- [ ] **No promotional or biased language** (neutral, factual tone)
- [ ] **Links are working** and point to official sources
- [ ] **Spelling and grammar are correct**
- [ ] **Commit message is descriptive** and follows conventions

## Review Process

1. **Maintainers will review** your PR within 5-7 business days.
2. **Feedback or requests for changes** will be provided in comments.
3. **Once approved**, your PR will be merged and your contribution credited.
4. **You'll be added** to the contributors list (if desired).
